Options reset values, autos choose when to start

4.5 · Test runner · option · auto · box

What an option resets to, when auto fixtures start, and what box hides.

An option is a fixture that the config can set 1. The project’s use value replaces its default. test.use() in a describe overrides it again; the inner describe wins. The config cannot set a fixture that is not an option: the run stops with Fixture "account" cannot be overridden…. test.use({ baseURL: undefined }) does not pass undefined. It goes back to the config value, or to the default. To pass a real undefined, use a fixture function.

Source ↗

A fixture with auto: true starts even when no test names it 2. Before a test, auto fixtures start first: worker-scoped ones, then test-scoped ones. Then come the fixtures the test names. Each fixture still starts its own dependencies first, and a running fixture is reused. See 4.2 for dependency order and fixture lifetime.

beforeEach and afterEach get the test-scoped auto fixtures too. beforeAll and afterAll do not 3: they start only worker-scoped auto fixtures. An internal mode, all-hooks-included, lets Playwright’s trace recording run there as well. The test fixtures that a beforeAll uses end when that hook ends.

Source ↗

title renames the fixture’s step in the report and in its timeout message 4. box: true hides the fixture’s step and its child steps from the report. box: 'self' hides only the fixture’s own step. The fixture still runs and is timed the same way. An override without options keeps the title but drops box, so its step shows again.

Source ↗
