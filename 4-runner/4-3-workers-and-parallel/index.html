Workers take groups, shards keep them whole

4.3 · Test runner · fullyParallel · workers · shard

A group is the unit that a worker takes and a shard keeps whole.

Playwright first selects files and tests, then cuts them into groups 1. testMatch, testIgnore and grep decide what runs. A group is the smallest unit that a worker takes. Tests in one group run in order, in one worker.

By default, one file is one group 2. More workers then help only when you have more files. With fullyParallel: true, each test can be its own group. A serial describe stays one group. Tests that share a beforeAll go into a few batches.

Source ↗

A shard takes whole groups 3. Playwright balances shards by test count. A large group cannot be split, so one shard can get more tests than the others. Fully parallel tests spread more evenly.

The reporter’s first line shows Running 12 tests using 4 workers, shard 1 of 3 4. The test count is for this shard. The worker count is planned capacity, calculated before dispatch. A free slot takes a group only when project limits and scheduling locks allow it. It reuses a worker from the same project with the same worker fixtures. Otherwise Playwright starts a new worker.

What you see in the call log

  • Running 12 tests using 4 workers, shard 1 of 3The tests selected for this shard and its planned worker capacity, calculated before dispatch. This does not count processes actually started.
