A retry is a new attempt in a new worker

4.4 · Test runner · retries · repeatEach

What a retry repeats, and what flaky means in the summary.

A failed test gets another attempt while retries allows it 1. With retries: 2, a test has at most three results. The failed attempt has stopped its worker, so the retry starts in a fresh one. The list reporter marks it (retry #1).

In a serial describe, one failure skips the tests after it 2. The retry then runs the whole describe again. Tests that passed before run again too.

Source ↗

A test that fails and then passes is flaky 3. The summary counts it under 1 flaky and lists it. Its first failure stays in the report. When a retry fails too, its errors follow a Retry #1 line. A test marked test.fail() works the other way: its failure is expected.

repeatEach is not a retry 4. It copies every test before the run, passing or not. Each copy is a separate test with its own result.

What you see in the call log

  • (retry #1)The list reporter runs this test a second time. The number counts attempts after the first.
  • Retry #1 ────────In the failure report, the errors below this line belong to the second attempt. Attempts without errors print no such line.
  • 1 flakyA test failed first and then passed on a retry. Its first failure is still in the report.
