Each clock spends its own remaining budget

4.6 · Test runner · test.setTimeout() · timeout

Read the remaining budget, then read which timer failed.

The output shown here is from Node.

The test clock keeps elapsed time between pieces of work 1. A test fixture without its own timeout spends that same budget during setup. If setup spends 20 seconds of 30, the body has about ten seconds left.

Source ↗

An explicit fixture timeout selects a separate clock 2. Its setup time does not spend the test clock. Setup and teardown share that fixture clock: 40 seconds of setup leaves about 20 from a 60-second budget.

A click starts its own action timer 3. A five-second click can fail while the test still has time. A longer click timeout does not extend the test budget. Setting the click timeout to zero removes only that action deadline.

After the test body, after hooks and fixture teardown get a fresh budget 4. When teardown uses it up, you see Tearing down "account" exceeded the test timeout of 30000ms. A fixture with its own timeout keeps its own clock instead. If that clock is already empty, Playwright skips its teardown.

What you see in the call log

  • Test timeout of 30000ms exceeded.The test body exhausted its shared test budget.
  • Test timeout of 30000ms exceeded while setting up "account".This fixture has no separate budget. Setup exhausted the test budget.
  • Fixture "account" timeout of 60000ms exceeded during setup.The fixture exhausted its own budget before use().
  • Fixture "account" timeout of 60000ms exceeded during teardown.Setup and teardown exhausted the fixture's shared budget.
  • locator.click: Timeout 5000ms exceeded.The click's own timer expired while the test still had time.
  • Tearing down "account" exceeded the test timeout of 30000ms.Teardown after the test used up its fresh budget. Only a fixture with its own timeout keeps its own clock here.
