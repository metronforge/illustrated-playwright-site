Projects wait for successful dependencies

4.1 · Test runner · projects · dependencies

Configuration becomes phases with a separate success gate.

The CLI builds overrides; Playwright loads, validates and normalizes configuration 1. For retries, the first defined value wins: CLI, project, root configuration, then zero. Zero counts as defined. use merges properties from root, project and CLI; later defined properties win.

Source ↗

Project names become dependency and teardown links 2. Phases place dependencies before their consumers. Before dispatch, Playwright checks success separately. An unsuccessful dependency blocks its consumers. A project enters the successful set only without worker errors, unsuccessful dependencies or tests that are not OK.

Source ↗

A teardown project waits for its setup project and that project’s consumers 3. It cannot have dependencies of its own: Playwright stops with Teardown project clean must not have dependencies. In this graph, failed setup blocks web, but clean can still run. Listing projects in an array does not express this ordering.

For an ordinary run, webServer is a runner plugin, before globalSetup and project tests 4. It reuses an available server when allowed, or starts one and waits for readiness. A readiness error stops later setup tasks. These are run tasks, outside fixture scopes. globalSetup receives configuration and may return cleanup; registered task cleanup runs in reverse order.
