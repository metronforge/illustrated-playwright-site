Codegen records what you meant, not every event

6.2 · Tracing · codegen · page.pause()

How clicks and keys become a few lines of test code.

Codegen listens to the page while you work in it 1. It sees clicks, typing and keys. A click on a checkbox becomes check() or uncheck(). Typing becomes one fill() with the final value, not one line per key.

For each action, codegen picks a locator 2. It builds several candidates and ranks them. It checks each one against the current page, so the chosen locator finds this element. It uses the test ID attribute that your config names.

Codegen joins actions before it writes code 3. Two fills of the same field keep only the last value. A double click replaces the single click that came just before it. So the code is shorter than the list of events.

Source ↗

Read the generated code before you keep it 4. For a file upload, codegen records only the file name from the browser. Your test needs a path that exists on its machine.
