A trace joins events with selected snapshots

6.1 · Tracing · context.tracing · trace

Choose what to capture, save each chunk, and decide which traces to keep.

context.tracing.start() sets capture options and starts the first chunk 1. Each chunk records calls until you stop it. Stopping a chunk stops recording calls, but keeps your capture options. Starting another chunk discards one still recording. Give each saved chunk a path.

A trace records calls before they run, before input, and after they finish 2. Use snapshots: true for DOM snapshots and network recording. Use screenshots: true for screenshot frames. Browser script bodies are omitted unless you use live. Response bodies can also fail to load.

Browser chunks share network resources so later snapshots can use them 3. Each API chunk starts with an empty network file. With runner tracing enabled, new browser and API contexts start their traces. API requests contribute network records when requests finish. API contexts have no browser DOM snapshots.

Source ↗

Runner tracing includes test steps and assertions 4. Manual browser tracing alone does not include assertions. trace: 'retain-on-failure' records before the result exists. It discards the trace when actual and expected status match. trace: 'on-first-retry' records only retry index one.
