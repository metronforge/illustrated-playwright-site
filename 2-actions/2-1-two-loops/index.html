Two loops behind every click

2.1 · Actions · locator.click()

What Playwright does between your click() call and the mouse event.

First, Playwright finds the element 1. If no element matches, it waits and looks again. If two or more elements match, the click fails at once 5.

Then Playwright tries to click that element 2. Each try checks the element in this order: stable 3, visible, enabled. Then Playwright scrolls the element into view. It also makes sure that no other element covers the click point.

Source ↗

If a check fails, Playwright waits and tries the same element again 4. It does not find the element again. It does that only if the app removed the element from the page.

Source ↗

Both loops stop at the action timeout. Then the last line of the call log tells you which check failed.

Concepts on this spread

Your test

  • LocatorA recipe: a frame and a selector string, without an element yet.Source ↗
  • Action timeoutOne deadline for both loops; the last log line names the failed check.Source ↗

Outer loop · find the element

  • Outer loopResolves the locator; with no match it waits and looks again.Source ↗
  • Selector enginePage code that turns one selector part into elements.Source ↗
  • Strict modeTwo or more matches fail at once, with no wait.Source ↗
  • DetachedThe app removed the element; only then the outer loop looks again.Source ↗

Inner loop · try this element

  • Inner loopTries to act on the element the outer loop found.Source ↗
  • Actionability checksStable, then visible and enabled, then the hit target; run in the page.Source ↗
  • StableThe element's box stays the same between animation frames.Source ↗
  • Hit targetThe element at the click point is the target or inside it.Source ↗
  • RetryA failed check ends one try; the next try reuses the element.Source ↗

What you see in the call log

  • element is not stableThe element moves. Playwright did not check visible and enabled yet.
  • … intercepts pointer eventsAnother element covers the click point.
  • retrying click actionPlaywright tries the same element again.
  • element was detached from the DOM, retryingThe app replaced the element. Playwright finds it again.
  • strict mode violationTwo or more elements match. Make the locator more specific.

  • DiffersDetached elementDocs: click() fails. Code: Playwright finds the element again and retries until the timeout. docs · code
