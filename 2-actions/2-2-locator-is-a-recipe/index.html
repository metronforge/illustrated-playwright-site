A locator stores the recipe, engines find the elements

2.2 · Actions · locator · filter · frameLocator

How a chain of locator calls becomes a search inside the page.

A locator stores a frame and a selector string 1. Chaining adds parts to that string. getByRole adds an internal role selector; getByText adds an internal text selector. Building this recipe does not select an element.

filter returns another locator with extra conditions 2. A has condition carries an inner selector. first() adds nth=0; nth(1) adds nth=1. These numbers select from the matches when the recipe runs.

Source ↗

When a click needs elements, the server runs the parsed selector inside the page 3. Each part uses a selector engine, such as CSS, text or role. Matches from one part become search roots for the next. A has engine keeps a candidate only when its inner search matches there. The call log prints the recipe back as code, so a wrong inner recipe shows there.

frameLocator adds an enter-frame part before its child selector 4. The server splits the recipe there. It finds the iframe, gets its content frame, then runs the remaining parts in that frame. The stored starting frame and the final search frame can differ.
