Each wait repeats a different piece of work

5.1 · Assertions · expect() · poll() · toPass()

Find the loop before deciding what can run again.

A locator text assertion sends its selector and expected text to the server 1. The server checks once, then retries if the result does not match. Each retry resolves the selector again and runs the page’s injected check. The test does not rerun the surrounding statements.

expect.poll repeats your value-producing function in the test worker, then checks its returned value 2. Matcher failures trigger another attempt. An error from the function itself escapes that retry catch. Poll refuses locator matchers such as toHaveText: they already retry on their own. Positive toPass instead repeats the whole block when it throws, including earlier requests or actions.

Source ↗

Poll inherits the expect timeout, normally 5000 milliseconds 3. toPass uses separate settings and defaults to zero. Both default to waits of 100, 250, 500, then 1000 milliseconds; the last interval repeats. Neither schedules a wait that reaches its deadline. In a running test, both cap their deadline 250 milliseconds before the test deadline, including with zero timeout. Server assertion backoff uses a different schedule, shortened for small timeouts.

Soft assertions change failure handling in the runner 4. With a runner step, a failed soft assertion records the error and lets execution continue. It still fails the test. Poll forces its inner matcher to throw, so mismatches can trigger retries before the outer assertion handles failure. A soft assertion inside toPass can therefore let the block finish without triggering another attempt.
