A failed call comes back with its name and its call log

1.1 · Messages · locator.click()

Each call goes out as a numbered message and comes back as a reply.

The output shown here is from Node.

await locator.click() sends one message 1. It names the object, the method and the parameters, and it has a call number. Your test then waits for the reply with that number. 0.1 API calls leave from Node, page calls from the browser shows where the two ends run.

Source ↗

The server side does the work and speaks the browser’s own protocol 2. In Chromium, the click becomes Input.dispatchMouseEvent messages. They have their own numbers, separate from your call. One call can send several browser messages. With browserType.connect(), your messages also cross a WebSocket to a remote server.

The reply carries the same call number 3. On success, your await returns. On failure, the server sends the error together with the log lines it wrote for this call. When the server recorded log lines, the client adds them under Call log:.

Source ↗

Then the client puts the API name in front: locator.click: Timeout 5000ms exceeded. 4. For this timeout, the name, the reason and the call log form one message. A new error that replaces this message loses that information.

What you see in the call log

  • locator.click: Timeout 5000ms exceeded.The client put the API name in front of the server's error. The name tells you which call in your test failed.
  • Call log:The lines below it are the server's log for this one call. Read the last line first.
