Your script and Playwright's checks share the page, not its variables

1.3 · Messages and objects · page.evaluate()

Your code and Playwright's checks see the same elements, but not the same variables.

page.evaluate() runs your function in the page’s own JavaScript 1. Playwright calls this the main world. Your function sees the page’s variables, such as window.app. Playwright runs its own checks in a second, separate copy of JavaScript: the utility world.

Both worlds see the same DOM, but each has its own variables 2. A variable that the page sets is not visible in the utility world. Playwright’s own checks therefore do not depend on page globals. Some selector engines ask for the main world, so those run there.

A new-document navigation destroys the old JavaScript worlds, and the new document gets new ones 3. Playwright’s own element steps notice this and retry in the new world. Your page.evaluate() does not retry. If the page navigates while it runs, it fails with Execution context was destroyed.

Source ↗

A handle belongs to the world where it was made 4. After a new-document navigation, that world is gone. Passing an old handle to page.evaluate() fails at once. Get a new handle from the new document.

What you see in the output

  • Execution context was destroyed, most likely because of a navigationYour page.evaluate() was still running when the page navigated. Wait for the new page, then evaluate again.
  • JSHandles can be evaluated only in the context they were created!A handle from the old document was passed to code in the new one. Get a fresh handle after navigation.
