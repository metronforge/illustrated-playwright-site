Contexts divide state, pages contain frame trees

1.2 · Messages and objects · browser · context · page · frame

What a context keeps apart, and how closing moves down the tree.

A browser holds contexts, a context holds pages, and a page holds frames 1. Each page has one main frame. Every iframe adds a child frame under it. Locators and actions always run in one frame of this tree.

A context keeps its own cookies and local storage 2. Two contexts that open the same site do not share them. In Chromium, each context is a separate browser context with its own ID. Cookie reads and writes carry that ID.

Source ↗

Closing moves down the tree 3. Closing a context closes all its pages; other contexts keep working. Closing the browser closes every context. browser.newPage() creates a hidden context for that page, so page.close() closes that context too.

Source ↗

A call whose page object is gone finds no target on the server 4. Playwright answers it with Target page, context or browser has been closed. The message does not say which close ran. Look for the close() call, the end of a fixture, or a browser crash before it.

What you see in the output

  • Target page, context or browser has been closedThe test used a page after its page, context or browser closed. Find which close ran first.
