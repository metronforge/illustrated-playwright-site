Fallback passes the request to the next handler

3.1 · Request, route and HAR · route.fallback()

A handler can pass the request onward or end the chain.

Page handlers get the first turn 1. Each scope runs matching handlers in reverse registration order. Playwright copies each scope’s list before walking it. Unhandled page requests then enter the context list.

fallback() stores changes and lets the next matching handler run 2. continue() sends the request onward and ends the user handler chain. Use fallback when an earlier handler must still supply the response.

Source ↗

Overrides stay on this request through later handlers 3. Omitted fields keep earlier values; supplied headers replace the stored header object. A changed URL also affects later client matching in this version. It does not restart browser interception or revisit handlers already checked. In Chromium, redirected requests retain header overrides through an explicit repair step.

fulfill() supplies a response; abort() fails the request 4. Both end the chain. Chromium sends separate browser commands for continue, fulfill and abort. Service workers need care. The docs recommend serviceWorkers: 'block' because page routes miss requests answered by a worker. Separately, intercepted worker-owned requests in Chromium go directly to context handlers.
